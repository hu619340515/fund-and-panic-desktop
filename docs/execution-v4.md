# 基金申赎提交日核验

`risk_v4/execution.py` 使用本地 AKShare 1.18.94 的 `fund_purchase_em` 所定义的东方财富公开申赎状态接口与原始列顺序，按六位基金代码选取唯一记录。请求有连接及读取超时、25 秒读取上限和响应尺寸上限；读取、解码、代码匹配任一失败均返回 `verified=false`，不把异常当成开放状态。返回原始申赎文字、来源“下一开放日”、日累计限额以及响应 SHA-256，便于审计；不采用公开费率替代用户录入的每批次费率。

只有可识别的普通国内基金类型、明确“开放申购/赎回”或“暂停申购/赎回”状态，以及可核实的 XSHG 交易日，才给出相应方向的 `next_subscription_date` / `next_redemption_date`。上海时间 15:00 前当日可提交；15:00 起顺延下一交易日。公开源注明将来开放日时，必须落在交易日且以更晚日期为准。状态文字为“限大额”等含义未核实时，该方向的 `subscription_verified/redemption_verified=false`、对应提交日留空；另一方向若明确开放，仍可核实，不因申购限额关闭赎回。两侧均未知、基金类型无法核实或 QDII、跨境、场内交易等规则不同者 `verified=false`，不推断可申报日。公开列表的日累计限定金额常为正数；状态明确开放时仍可核实**提交日**，但记为 `open_with_limit` 并保留“限额剩余及订单金额匹配”缺项，不能据此认为订单金额可获接受。即使今天申赎均暂停，状态也如实核实为 `closed`，可提交日保持空值。

这里的“可提交”仅指国内标准场外基金在公开规则下允许发起申请，不保证平台实际接受、最终成交、成交净值、份额确认天数或赎回到账日。接口将 `confirmation_days` 留空，`missing` 明列未知条件。组合层只能将已核实且方向相符的提交日作为人工复核参考，不能据此标识精确可成交金额或可到账现金。上线时仍应记录实际请求时间及来源状态供日后审计；本模块的模拟单测不能替代当日公开页面和券商渠道验证。
