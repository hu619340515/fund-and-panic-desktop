# 旧模型审计与重建基线

本次重建以仓库 `v2.0.4`（`254d9f913c1db0a6ba5c046c36af7a2fd85197b1`）为软件基线。旧数据库和用户基金清单保留，旧模型分数不参与 v4 状态校准、预测训练、图表或策略回测。

## 旧系统问题与处理

| 问题 | 对结果的影响 | 3.0.0 的处理 |
|---|---|---|
| 人工锚点、历史分位混合及递归显示平滑 | 同一压力值的解释与刷新路径相关 | 对真实价格原始特征求过去分位；同一数据和模型配置得到同一收盘结果 |
| 可选来源缺失时重新分配权重 | 数据断档会改变分数含义 | 三核心特征等权固定；QVIX、IF、宽度、涨跌停只作佐证 |
| 盘中暂定值与收盘最终值容易混淆 | 暂定估值可能被误读为正式历史 | 盘中行情单独展示，状态分仅用完整日线，历史回算与实际发布分表 |
| 旧历史估计缺项后仍有一条总分曲线 | 精度及时间可得性不透明 | 不接旧曲线；新曲线只回算完整真实输入，缺失日期留空 |
| 状态分被误解为未来风险 | 0–100 分并不是跌幅事件概率 | 独立的事件模型、期末收益区间及时间外验证门槛 |
| 用市场总分直接指导不同基金 | 港股、行业、主动基金暴露各不相同 | 基金基准单独核实，真实分红/拆分收益核对暴露，未核实关闭操作 |
| 缺少组合相关性、费用及交易限制 | 逐基金建议不等于可执行的组合 | 联合协方差和风险/现金/集中度/调仓幅度约束；冲突不输出假目标 |

旧 V3 代码和 v1 诊断接口为已有记录的本地排查保留；正式客户端仅调用 v2 风险和持仓接口。新模型不调用旧评分函数。这个兼容边界由桌面 IPC 测试、新模型测试及分表测试共同检查。

## 可复现基线

1. 旧离线夹具继续检查旧数据读取及迁移兼容；这些夹具不是新模型的市场有效性证据。
2. 新单元测试检查固定权重、方向、零值、历史时间窗、50日标签隔离、分位目标、概率单调与白名单。
3. 新服务测试检查 V5→V6 含 WAL 的迁移备份、正式记录不可覆写、修订留档、行情失败不掩盖已有历史、CSV预览不写库及多进程回收。
4. `engine/scripts/risk_v4_cli.py` 在指定隔离库中抓取真实行情、训练和回放；`risk_v4_report.py` 从该库重现参数、指标与中文 CSV。
5. 最终 EXE 使用相同生产 `spawn` 路径完成成功、异常退出、异常返回、硬超时和实际机器学习训练测试。合成数据明确限定为程序测试。

## 交付门槛

当前状态、真实历史、基金估值和持仓管理可以独立使用。概率须逐项通过时间外统计及历史可得性核验；操作建议还须通过成本后策略验证和20个交易日实际观察。模型没有通过验证时，软件必须诚实显示原因，不能通过调整测试段参数或填数字使验收看起来通过。

本次可复现研究回放、数据来源与软件检查随交付提供。实际观察天数由客户端按真实交易日累计，周末重复运行、历史补算和离线夹具都不能增加天数。
